# v0.3.1 Fix Plan：实体问答加权检索与首次出现保护

版本：v0.3.1  
日期：2026-07-04  
基线版本：v0.3 实体索引与实体时间线  
目标：修复实体首次出现和实体生命周期问答被后期向量召回误导的问题

## 1. 问题背景

v0.3 已建立实体索引、实体提及、实体时间线和实体关系，但测试发现：

```text
实体详情页：斩龙闪首次出现 = 第8章《斩龙之刃》
问答页：斩龙闪首次出现 = 第3681章
```

这说明实体数据本身有正确证据，但问答阶段仍然被后期向量召回片段影响。

## 2. 根因

### 2.1 实体证据和向量证据混排

当前实体问题会：

```text
实体检索 -> entity_chunks
向量检索 -> vector_chunks
合并排序 -> LLM 生成
```

由于后期章节文本更丰富、语义相似度更高，LLM 容易忽略实体库中的最早提及。

### 2.2 首次出现属于结构化事实

“第一次出现在哪”不是开放生成问题，而是结构化排序问题。  
它应由 `entity_mentions` 中最早的明确提及决定，不能由向量相似度决定。

### 2.3 实体时间线噪声过大

当前实体时间线只要 chunk 中出现实体名和事件词，就可能生成事件。  
但事件词可能不在实体附近，导致“斩龙闪生命周期”出现大量低价值事件。

## 3. v0.3.1 修改目标

1. 实体问题采用实体优先的加权检索。
2. `entity_first_seen` 增加不可被向量覆盖的硬约束。
3. `entity_timeline` 改为实体附近窗口匹配，降低噪声。
4. LLM prompt 增加结构化结论块。
5. 前端展示实体证据权重、证据来源和保护状态。

## 5. 实体加权检索设计

### 5.1 通用实体评分

所有实体候选证据增加以下字段：

```json
{
  "entity_score": 1.0,
  "order_score": 0.92,
  "keyword_score": 0.8,
  "vector_score": 0.2,
  "confidence_score": 0.95,
  "final_score": 0.91,
  "protected": true,
  "source": "entity_mention"
}
```

### 5.2 entity_first_seen 权重

首次出现问题：

```text
final_score =
  entity_score     * 0.50
  order_score      * 0.35
  keyword_score    * 0.10
  vector_score     * 0.03
  confidence_score * 0.02
```

说明：

1. `entity_score`：实体库明确命中实体，通常为 1。
2. `order_score`：章节越早分越高。
3. `keyword_score`：证据包含首次出现、登场、获得等词加分。
4. `vector_score`：只作为微弱辅助。
5. `confidence_score`：来自 mention 或规则置信度。

### 5.3 entity_timeline 权重

实体变化问题：

```text
final_score =
  entity_nearby_score * 0.35
  event_word_score    * 0.25
  confidence_score    * 0.20
  chapter_score       * 0.10
  vector_score        * 0.10
```

重点：`entity_nearby_score` 必须来自实体附近窗口，而不是整个 chunk。

### 5.4 entity_relation 权重

实体关系问题：

```text
final_score =
  entity_pair_score   * 0.35
  relation_word_score * 0.25
  confidence_score    * 0.20
  chapter_score       * 0.10
  vector_score        * 0.10
```

如果只是共同出现但没有关系词：

```text
relation_type = related_to
confidence_score <= 0.45
protected = false
```

## 6. 首次出现硬约束

`entity_first_seen` 必须遵守：

1. 主答案只能来自 `entity_mentions`。
2. 最早 `explicit` mention 是 protected evidence。
3. 后期向量召回不能覆盖 protected evidence。
4. 向量 chunk 只能进入“补充片段”，不能进入“首次出现候选”。
5. 引用章节第一项必须是最早 mention 的章节。

伪代码：

```python
if query_type == "entity_first_seen":
    mentions = get_entity_mentions(entity_id)
    mentions = score_mentions(mentions)
    earliest = select_protected_first_seen(mentions)
    chunks = [earliest_as_chunk]
    supplemental = vector_search(question, top_k=3)
    return {
        "chunks": chunks + supplemental,
        "protected_answer": {
            "entity": entity_name,
            "first_seen_chapter": earliest.chapter_no,
            "first_seen_title": earliest.chapter_title,
            "chunk_id": earliest.chunk_id
        }
    }
```

LLM prompt 中加入：

```text
【结构化结论】
实体：斩龙闪
问题类型：首次出现
受保护结论：斩龙闪首次出现于第8章《斩龙之刃》。
你必须以该结论为准，不能根据后期向量片段改写首次出现章节。
```

更进一步，v0.3.1 可以直接跳过 LLM，程序生成回答：

```text
根据实体索引，斩龙闪首次明确出现于第8章《斩龙之刃》。
依据：实体提及记录 {chunk_id}
```

MVP 推荐：先保留 LLM，但强插结构化结论块。

## 7. 实体时间线降噪

### 7.1 附近窗口匹配

修改 `scripts/build_entities.py`。

当前逻辑：

```text
chunk 中出现实体名 + chunk 中出现事件词 -> 生成事件
```

改为：

```text
找到实体名位置
截取前后 window=120 字
只在窗口中匹配事件词
```

伪代码：

```python
def entity_windows(text, aliases, window=120):
    for alias in aliases:
        for pos in find_all(text, alias):
            yield text[max(0, pos-window): pos+len(alias)+window]
```

### 7.2 事件去重

同一实体、同一章节、同一事件类型：

```text
只保留 final_score 最高的一条
```

去重 key：

```text
(entity_id, chapter_no, event_type)
```

### 7.3 置信度过滤

默认输出到前端的实体时间线：

```text
confidence >= 0.65
```

低于阈值的仍可保留在 JSONL，但前端默认折叠到“低置信候选”。

## 8. 检索路由修改

修改 `retrieval_router.py`：

### 8.1 entity_first_seen

不再调用普通 `_merge_and_rank()` 混排。

```text
entity_first_seen:
  entity_chunks = protected first_seen mention
  vector_chunks = supplemental only
  merged = entity_chunks + vector_chunks[:3]
```

### 8.2 entity_timeline

```text
entity_timeline:
  entity_timeline_events scored by entity timeline formula
  sort by chapter_no asc, then final_score desc
  vector only supplements missing context
```

### 8.3 entity_relation

```text
entity_relation:
  relation edges scored by relation formula
  high-confidence relations first
  related_to candidate lower priority
```

## 9. query_service 修改

`generate_answer()` 增加 `protected_answer` 参数。

Prompt 结构：

```text
系统规则

结构化结论：
...

实体证据：
...

补充片段：
...

用户问题：
...
```

如果存在 `protected_answer` 且类型为 `entity_first_seen`：

1. prompt 中明确“必须使用受保护结论”。
2. answer 后处理检查章节号是否匹配。
3. 如果 LLM 输出与 protected answer 冲突，使用程序模板覆盖。

后处理规则：

```python
if protected_answer and str(protected_chapter) not in answer:
    answer = render_protected_answer(protected_answer)
```
