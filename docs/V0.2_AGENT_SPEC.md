# v0.2 Agent Spec：时间线索引与问题路由实施规格

版本：v0.2  
日期：2026-07-03  
依赖文档：[V0.2_DESIGN.md](./V0.2_DESIGN.md)  
基线：v0.1 本地小说 RAG

## 1. 实施目标

在 v0.1 基础上增加时间线索引、问题识别、检索路由和顺序型问题保护，解决“第一个/首次/最早”类问题被后期相似章节误导的问题。

重点案例：

```text
问题：苏晓进入的第一个世界是什么？
错误表现：回答《Fate/Zero》，依据第3498章《进入》
v0.2 目标：不能仅根据后期章节断言第一个世界；必须优先查找早期 world_entry 时间线事件，证据不足则明确说明。
```

## 3. 实施顺序

### 阶段 1：问题识别器

创建 `backend/app/services/question_classifier.py`。

实现：

```python
def classify_question(question: str) -> dict:
    ...
```

输出结构：

```json
{
  "query_type": "sequence_first",
  "entities": ["苏晓"],
  "event_hints": ["进入世界"],
  "time_constraint": "earliest",
  "confidence": 0.9
}
```

规则：

1. 包含 `第一个`、`第一次`、`首次`、`最早`、`初次`、`最开始` -> `sequence_first`。
2. 包含 `时间线`、`经历`、`全过程`、`发展脉络` -> `timeline_summary`。
3. 包含 `哪一章`、`在哪章`、`出现章节`、`登场章节` -> `chapter_lookup`。
4. 包含 `顺序`、`先后`、`依次`、`第几次` -> `sequence_order`。
5. 否则 -> `normal_fact`。

事件提示识别：

```text
进入/世界/衍生世界 -> 进入世界
回归/结算/返回 -> 回归乐园
任务/主线/支线 -> 任务
获得/得到/拿到 -> 获得
登场/遇到/见到 -> 角色相遇
```

验收：

```text
苏晓进入的第一个世界是什么？ -> sequence_first, event_hints contains 进入世界
斩龙闪最早在哪章出现？ -> sequence_first or chapter_lookup
按章节顺序整理苏晓早期进入过的世界 -> timeline_summary or sequence_order
```

### 阶段 2：时间线构建脚本

创建 `scripts/build_timeline.py`。

输入：

```text
data/{project_id}/chunks.jsonl
```

输出：

```text
data/{project_id}/timeline_events.jsonl
data/{project_id}/timeline_index.json
```

命令：

```powershell
python scripts/build_timeline.py --project reincarnation_paradise
```

抽取事件类型：

```text
world_entry
world_return
task_start
task_complete
item_obtained
skill_obtained
character_meet
power_upgrade
major_event
```

MVP 必须先实现：

```text
world_entry
world_return
task_start
task_complete
```

事件结构：

```json
{
  "event_id": "reincarnation_paradise_evt_000001",
  "project_id": "reincarnation_paradise",
  "event_type": "world_entry",
  "chapter_no": 6,
  "chapter_title": "这是，真实的世界",
  "chunk_id": "reincarnation_paradise_ch0006_0001",
  "subjects": ["苏晓"],
  "objects": [],
  "world_name": null,
  "event_summary": "检测到疑似进入世界事件。",
  "evidence": "短证据片段",
  "confidence": 0.7,
  "extract_method": "rule"
}
```

规则要求：

1. 每个事件必须有 `chapter_no`、`chapter_title`、`chunk_id`。
2. `evidence` 最长 300 字。
3. 同一 chunk 对同一 event_type 最多生成一个事件。
4. 按 `chapter_no`、`chunk_id` 排序写入。
5. 不输出大段原文。

world_entry 关键词：

```text
进入衍生世界
进入世界
新的衍生世界
猎杀者即将进入
传送开始
传送中
世界难度
世界之源
主线任务
```

world_return 关键词：

```text
回归乐园
返回轮回乐园
回到轮回乐园
世界结算
开始结算
任务完成
传送回
```

task_start 关键词：

```text
主线任务
支线任务
隐藏任务
天赋觉醒任务
任务简介
任务难度
任务奖励
任务惩罚
```

task_complete 关键词：

```text
任务完成
主线任务已完成
支线任务已完成
结算奖励
```

验收：

1. 文件生成成功。
2. `timeline_events.jsonl` 不为空。
3. 至少能抽到早期章节的 world_entry 候选。
4. 事件按章节号升序。

### 阶段 3：时间线服务

创建 `backend/app/services/timeline_service.py`。

实现：

```python
def load_timeline_events(project_id: str) -> list[dict]:
    ...

def query_timeline(
    project_id: str,
    event_hints: list[str],
    entities: list[str],
    query_type: str,
    limit: int = 10,
) -> list[dict]:
    ...
```

映射规则：

```text
进入世界 -> world_entry
回归乐园 -> world_return
任务 -> task_start/task_complete
获得 -> item_obtained/skill_obtained
```

排序：

1. `sequence_first`：优先 event_type 匹配，然后 chapter_no 升序。
2. `timeline_summary`：chapter_no 升序。
3. 其他：event_type 匹配优先，chapter_no 升序。

验收：

```text
query_timeline(..., event_hints=["进入世界"], query_type="sequence_first")
```

应返回早期 `world_entry` 候选，而不是第3498章优先。

### 阶段 4：关键词检索

创建 `backend/app/services/keyword_service.py`。

实现：

```python
def keyword_search(project_id: str, keywords: list[str], limit: int = 20) -> list[dict]:
    ...
```

输入来源：

```text
data/{project_id}/chunks.jsonl
```

返回结构与向量 chunk 兼容：

```json
{
  "chunk_id": "...",
  "chapter_no": 6,
  "chapter_title": "...",

  "score": 0.8,
  "source": "keyword"
}
```

排序：

1. 命中关键词数量多优先。
2. 如果是顺序型问题，章节号早优先。

验收：

关键词 `["进入世界", "衍生世界", "世界难度"]` 应能召回早期世界相关章节。

### 阶段 5：检索路由

创建 `backend/app/services/retrieval_router.py`。

实现：

```python
def retrieve_evidence(project_id: str, question: str, top_k: int | None = None) -> dict:
    ...
```

返回：

```json
{
  "query_analysis": {},
  "chunks": [],
  "timeline_events": [],
  "retrieval_debug": {
    "route": "timeline_plus_keyword_plus_vector",
    "vector_count": 8,
    "timeline_count": 3,
    "keyword_count": 5
  }
}
```

路由规则：

1. `normal_fact`：向量检索为主。
2. `sequence_first`：时间线 + 关键词 + 向量。
3. `sequence_order`：时间线 + 关键词，按章节升序。
4. `timeline_summary`：时间线为主。
5. `chapter_lookup`：关键词 + 向量，首次类问题按章节升序。

合并规则：

1. 相同 `chunk_id` 去重。
2. 时间线事件优先保留。
3. 顺序型问题中，早期高置信时间线事件排在前面。
4. 向量召回只作为补充，不允许单独决定“第一个”。

### 阶段 6：Evidence Guard

在 `retrieval_router.py` 或 `query_service.py` 中实现：

```python
def guard_evidence(query_analysis: dict, evidence: dict) -> dict:
    ...
```

规则：

1. `sequence_first` 但没有 timeline_events 时，标记 `insufficient_order_evidence = true`。
2. 如果所有候选章节都大于某个很晚阈值，例如 500，而问题问“第一个”，标记风险。
3. 如果向量最高分章节明显晚于时间线候选，不允许把向量最高分作为唯一答案依据。

输出：

```json
{
  "insufficient_order_evidence": false,
  "warnings": []
}
```

### 阶段 7：query_service 改造

修改 `backend/app/services/query_service.py`：

1. 不再直接只调用 `retrieve_chunks`。
2. 改为调用 `retrieval_router.retrieve_evidence`。
3. Prompt 中加入 query_analysis、timeline_events、guard warnings。
4. 返回结果增加 `query_analysis`、`timeline_events`、`retrieval_debug`。

Prompt 必须加入：

```text
如果用户询问“第一个、第一次、首次、最早、最开始”等顺序问题，你必须优先依据章节号最早且事件类型匹配的证据回答。
如果证据主要来自后期章节，不能断言它就是第一个。
如果没有足够证据确认顺序，回答“当前证据不足以确认第一个/首次”，并列出已找到的候选章节。
```

v0.2 完成必须满足：

1. 已生成时间线索引文件。
2. 查询接口返回问题分析结果。
3. 顺序型问题不再只由后期向量召回片段决定答案。

6. 原文文件未被修改。

## 6. 注意事项

1. PowerShell 对中文路径和中文输出有编码风险；新增批处理脚本时尽量使用 ASCII 提示，Python 文件用 UTF-8。
2. 时间线抽取先保守，不追求一次性覆盖所有事件。
3. 若事件抽取置信度不高，前端显示“候选事件”，不要显示为“确定事件”。
4. 不要为了修一个问题写死《轮回乐园》或“苏晓”的规则。
