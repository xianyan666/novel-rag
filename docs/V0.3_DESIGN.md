# v0.3 Design：实体索引、实体时间线与关系网络

版本：v0.3  
日期：2026-07-04  
基线版本：v0.2 时间线 RAG  
目标：解决人物、物品、技能等实体的首次出现、生命周期变化和实体关系查询

## 1. 背景

v0.2 已经通过问题识别、时间线索引和检索路由，改善了“第一个/首次/最早”等顺序型事件问题。例如“苏晓进入的第一个世界是什么”不应再仅靠后期相似章节回答。

但 v0.2 的索引主体仍然是事件类型，例如：

```text
world_entry
world_return
task_start
task_complete
```

这无法稳定回答实体类问题：

```text
斩龙闪第一次出现在哪？
斩龙闪后续发生了哪些变化？
莫蕾第一次登场在哪？
莫蕾和苏晓有哪些交集？
青钢影能力经历了哪些阶段？
```

这些问题需要面向“实体”的数据结构，而不是只面向“事件”的时间线。

## 2. v0.3 目标

v0.3 新增三类能力：

1. 实体索引：建立人物、物品、技能、地点、势力、世界等实体库。
2. 实体时间线：追踪实体首次出现、获得、升级、损坏、修复、关系变化等生命周期事件。
3. 实体关系：建立实体之间的关系边，例如人物互动、归属、持有、敌对、合作、技能来源、装备归属。

v0.3 后，系统应支持：

```text
实体首次出现
实体后续变化
实体档案
实体关系
实体相关章节定位
实体生命周期摘要
```

## 3. 设计原则

1. 不修改原文：所有实体数据写入 `data/{project_id}/`。
2. 证据优先：实体、提及、关系、时间线都必须可回溯到章节和 chunk。
3. 可迁移：不能写死《轮回乐园》或某个角色名，实体种子可配置化。
4. 渐进抽取：v0.3 MVP 先做规则和种子实体，后续再加 LLM 辅助抽取。
5. 候选透明：低置信结果以“候选”展示，不伪装成确定事实。
6. 分层索引：Vector Index 处理语义问答，Timeline Index 处理事件顺序，Entity Index 处理实体生命周期。

## 4. v0.3 总体架构

```text
原文 chunks
  -> 实体提及抽取 entity_mentions
  -> 实体归并 entities
  -> 实体时间线 entity_timeline
  -> 实体关系 entity_relations
  -> 实体检索路由 Entity Retriever
```

查询链路：

```text
用户问题
  -> Question Classifier
  -> Entity Detector
  -> Retrieval Router
    -> entity_first_seen: Entity Mention Index
    -> entity_timeline: Entity Timeline
    -> entity_relation: Entity Relations + Vector
    -> entity_profile: Entities + Mentions + Timeline
    -> normal_fact: Vector
    -> sequence_first: Timeline + Keyword + Vector
  -> Evidence Guard
  -> LLM Answer
  -> 前端展示实体、关系、证据和章节引用
```

### 5.1 entities.jsonl

实体主表，表示“系统知道哪些实体”。

```json
{
  "entity_id": "reincarnation_paradise_item_000001",
  "project_id": "reincarnation_paradise",
  "name": "斩龙闪",
  "type": "item",
  "subtype": "weapon",
  "aliases": ["斩龙之刃"],
  "first_seen_chapter": 8,
  "first_seen_title": "斩龙之刃",
  "first_seen_chunk_id": "reincarnation_paradise_ch0008_0001",
  "description": "苏晓的重要武器。",
  "confidence": 0.92,
  "status": "candidate",
  "extract_method": "seed+rule"
}
```

实体类型：

```text
character   人物
item        物品/装备
skill       技能/能力
place       地点
faction     势力/组织
world       世界/副本
concept     机制/设定概念
title       称号/身份
unknown     未分类
```

### 5.2 entity_mentions.jsonl

实体提及表，表示“某实体在哪些章节/chunk 出现过”。

```json
{
  "mention_id": "reincarnation_paradise_m_000001",
  "entity_id": "reincarnation_paradise_item_000001",
  "project_id": "reincarnation_paradise",
  "name": "斩龙闪",
  "matched_alias": "斩龙闪",
  "chapter_no": 8,
  "chapter_title": "斩龙之刃",
  "chunk_id": "reincarnation_paradise_ch0008_0001",
  "mention_type": "explicit",
  "evidence": "短证据片段",
  "confidence": 0.95
}
```

用途：

```text
首次出现查询
出现章节列表
实体热度统计
实体相关 chunk 召回
```

### 5.3 entity_timeline.jsonl

实体生命周期事件。

```json
{
  "entity_event_id": "reincarnation_paradise_et_000001",
  "entity_id": "reincarnation_paradise_item_000001",
```

```text
faction_joined          加入势力
faction_left            离开势力
status_changed          状态变化
```


## 6. 实体抽取策略

### 6.1 MVP 采用“种子实体 + 规则扫描”

先不要追求完全自动 NER。v0.3 MVP 使用可控方案：

```text
config/entities.seed.json
  -> 扫描 chunks
  -> 建立 mentions
  -> 归并 entities
  -> 抽取 timeline/relations
```

种子示例：

```json
[
  {
    "name": "苏晓",
    "type": "character",
    "aliases": ["白夜"]
  },
  {
    "name": "斩龙闪",
    "type": "item",
    "subtype": "weapon",
    "aliases": ["斩龙之刃"]
  },
  {
    "name": "莫蕾",
    "type": "character",
    "aliases": []
  }
]
```

### 6.2 自动候选实体

后续可从高频模式中抽取候选：

```text

称号 X
```

候选实体默认 `status = candidate`，需要通过证据或人工确认。

## 8. 检索路由升级

v0.3 路由：

```text
entity_first_seen
  -> Entity Mention Index
  -> 按 chapter_no 升序
  -> 返回首次明确提及

entity_timeline
  -> Entity Timeline
  -> Entity Mentions 补证据
  -> 按 chapter_no 升序

entity_profile
  -> Entities + Entity Timeline + Relations + Vector
  -> 输出档案摘要

entity_relation
  -> Entity Relations
  -> Vector 补充上下文
  -> 输出关系链和证据

entity_mentions
  -> Entity Mentions
  -> 按章节聚合
```

如果实体未在实体库中找到：

```text
1. 临时关键词扫描 chunks
2. 返回候选 mentions
3. 提示“实体尚未进入实体库，可构建/更新实体索引”
```

## 9. Evidence Guard 升级

新增实体保护规则：

1. `entity_first_seen` 必须按 `chapter_no` 最早的明确 mention 回答。
2. 不允许仅靠向量相似片段断言首次出现。
3. `entity_timeline` 必须按章节升序输出。
4. 如果实体别名冲突，必须提示候选歧义。
5. 如果关系边置信度低，前端显示为“候选关系”。

### 11.3 色彩与材质

建议 CSS 变量：

```css
:root {
  --bg: #f6f7fb;
  --surface: rgba(255, 255, 255, 0.78);
  --surface-solid: #ffffff;
  --text: #141a22;
  --muted: #697586;
  --line: rgba(20, 26, 34, 0.08);
  --accent: #ff6900;
  --accent-blue: #2f6bff;
  --success: #20a162;
  --warning: #d88a00;
  --danger: #d92d20;
  --shadow: 0 12px 32px rgba(17, 24, 39, 0.10);
}
```

风格规则：

1. 主背景使用浅色，不用大面积深色。
2. 面板使用半透明白色和轻微阴影。
3. 可使用 `backdrop-filter: blur(18px)`，但必须有纯色 fallback。
4. 强调色以橙色和蓝色为主，不做大面积渐变。
5. 工具页面保持信息密度，不做营销风 hero。

### 11.4 组件风格

1. 面板：轻玻璃质感，边框 1px，圆角建议 12px；若与现有组件冲突，普通小卡片保持 8px。
2. 按钮：主按钮橙色，次按钮白底细边框，危险操作红色。
3. 标签：实体类型用小色块，例如人物蓝、物品橙、技能紫、势力绿。
4. 时间线：纵向细线 + 章节节点 + 证据展开。
5. 关系图：默认列表/矩阵，图形视图作为增强，不阻塞 MVP。
6. 反馈：构建索引、构建实体库等长任务必须显示进度和日志。

## 12. v0.3 验收问题

必须通过：

```text
斩龙闪第一次出现在哪？
斩龙闪后续发生了哪些变化？
莫蕾第一次登场在哪？
莫蕾和苏晓有哪些交集？
青钢影能力经历了哪些变化？
列出斩龙闪相关的重要章节。
```

预期：

1. 首次出现问题优先查询 `entity_mentions`，不是纯向量检索。
2. 后续变化问题优先查询 `entity_timeline`。
3. 关系问题优先查询 `entity_relations`。
4. 所有回答都带章节引用。
5. 证据不足时明确说明。
