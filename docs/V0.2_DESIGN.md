# v0.2 Design：时间线索引与问题识别

版本：v0.2  
日期：2026-07-03  
基线版本：v0.1 本地小说 RAG  
目标：修复“第一个/首次/最早”等顺序型问题的误召回问题

## 1. 背景

v0.1 已完成本地小说 RAG 的基础链路：

```text
原文 -> 章节解析 -> chunk 切分 -> FAISS 向量索引 -> 检索 -> Ollama 回答 -> Vue 展示
```

该版本适合回答“某设定是什么”“某人物如何描述”等普通语义查询，但在顺序型问题上会出现明显偏差。例如用户问“苏晓进入的第一个世界”，系统却召回后期第3498章《进入》中《Fate/Zero》相关片段，并误答为第一个世界。

根因是：v0.1 只按向量相似度检索，不理解“第一个、首次、最早”这类时间顺序约束。

## 2. v0.2 目标

v0.2 在不推翻 v0.1 架构的前提下，新增三类能力：

1. 问题识别：判断用户问题属于普通设定问答、顺序型问题、章节定位、时间线查询、角色/道具查询等。
2. 时间线索引：从章节中抽取“进入世界、回归、任务开始、任务完成、重要事件”等时间线事件。
3. 检索路由：根据问题类型选择普通向量检索、时间线检索、关键词检索或混合检索。

v0.2 的重点不是生成游戏内容，而是提高“依据原文回答”的准确性，尤其是时间顺序类问题。

## 3. 设计原则

1. 原文不变：仍然不修改 `原文/`。
2. 可回溯：所有时间线事件必须带章节号、章节标题、chunk_id 或证据文本。
3. 可迁移：时间线抽取规则不能只服务《轮回乐园》，应支持其他小说配置扩展。
4. 保守回答：如果时间线证据不足，必须回答“当前证据不足”，不能用后期片段推断“第一个”。
5. 分层检索：普通问题继续走向量检索；顺序问题优先走时间线和章节顺序。

## 4. v0.2 总体架构

```text
用户问题
  -> 问题识别器 Question Classifier
    -> 普通设定问题：Vector Retriever
    -> 顺序型问题：Timeline Retriever + Keyword Retriever + Vector Retriever
    -> 章节定位问题：Keyword Retriever + Chapter Filter
    -> 时间线问题：Timeline Retriever
  -> Rerank / Merge
  -> Evidence Guard
  -> LLM Answer
  -> 引用章节 + 命中片段 + 证据类型
```

新增数据链路：

```text
chapters.jsonl / chunks.jsonl
  -> timeline_extract.py
  -> timeline_events.jsonl
  -> timeline_index.json
```

## 5. 问题识别设计

### 5.1 问题类型

v0.2 至少支持以下类型：

```text
normal_fact        普通设定/事实问题
sequence_first     第一个/首次/最早类问题
sequence_order     第几次/顺序/先后类问题
timeline_summary   某人物/地点/世界的时间线总结
chapter_lookup     某事件/道具/人物在哪章出现
unknown            无法判断
```

### 5.2 规则优先的分类器

MVP 不需要先用 LLM 分类，采用规则分类更稳定。

触发 `sequence_first` 的词：

```text
第一个
第一次
首次
最早
初次
起初
开端
最开始
一开始
首个
```

触发 `sequence_order` 的词：

```text
第几次
第几个
顺序
先后
依次
分别在哪
时间顺序
发展过程
```

触发 `timeline_summary` 的词：

```text
时间线
经历
全过程
发展脉络
事件脉络
按章节整理
```

触发 `chapter_lookup` 的词：

```text
哪一章

首次出现在哪
出现章节
登场章节
```

### 5.3 分类输出

```json
{
  "question": "苏晓进入的第一个世界是什么？",
  "query_type": "sequence_first",
  "entities": ["苏晓"],
  "event_hints": ["进入世界"],
  "time_constraint": "earliest",
  "confidence": 0.9
}
```

## 6. 时间线索引设计

### 6.1 时间线事件类型

v0.2 先抽取高价值事件：

```text
world_entry        进入世界/衍生世界/任务世界
world_return       回归乐园/返回现实/任务结束
task_start         主线任务/支线任务/天赋任务开始
task_complete      任务完成/结算
item_obtained      获得重要道具/装备
skill_obtained     获得技能/能力
character_meet     重要角色登场/相遇
power_upgrade      属性/技能/装备重大提升
major_event        难以归类但重要的剧情事件
```

### 6.2 时间线事件结构

`data/{project_id}/timeline_events.jsonl`：

```json
{
  "event_id": "reincarnation_paradise_evt_000001",
  "project_id": "reincarnation_paradise",
  "event_type": "world_entry",
  "chapter_no": 6,
  "chapter_title": "这是，真实的世界",
  "chunk_id": "reincarnation_paradise_ch0006_0001",
  "subjects": ["苏晓"],
  "objects": ["未知世界"],
  "world_name": null,
  "event_summary": "苏晓进入一个真实存在的衍生世界，并开始接触该世界任务。",
  "evidence": "短证据摘录，不超过必要长度",
  "confidence": 0.72,
  "extract_method": "rule"
}
```

字段说明：

1. `event_id`：稳定 ID。
2. `event_type`：事件类型。
3. `chapter_no`：核心排序依据。
4. `chunk_id`：用于回溯原文 chunk。
5. `subjects`：人物或主体。
6. `objects`：事件对象，例如世界、道具、任务。
7. `world_name`：如果能明确识别世界名则填写，否则为 null。
8. `event_summary`：用于检索和前端展示。
9. `evidence`：短证据，不输出大段原文。
10. `confidence`：抽取置信度。
11. `extract_method`：`rule`、`llm`、`manual`。

### 6.3 事件抽取策略

v0.2 MVP 使用规则抽取，不先依赖 LLM 批量抽取。

`world_entry` 触发模式：

```text
进入衍生世界
进入世界
传送开始
传送中
世界难度
世界之源
主线任务
新的衍生世界
猎杀者即将进入
```

`world_return` 触发模式：

```text
回归乐园
返回轮回乐园
任务完成
世界结算
开始结算
传送回
```

`task_start` 触发模式：

```text
主线任务
支线任务
隐藏任务
天赋觉醒任务
任务简介
任务难度
任务奖励
任务惩罚
```

### 6.4 时间线索引文件

`timeline_events.jsonl` 是主数据。  
`timeline_index.json` 是便于快速查询的辅助索引：

```json
{

    "苏晓": ["reincarnation_paradise_evt_000001"]
  },
  "by_chapter": {
    "6": ["reincarnation_paradise_evt_000001"]
  }
}
```

## 7. 检索路由设计

### 7.1 普通问题

```text
normal_fact -> Vector Retriever -> LLM
```

沿用 v0.1。

### 7.2 第一个/首次/最早问题

```text
sequence_first
  -> Timeline Retriever: 按 event_type 和主体过滤
  -> Keyword Retriever: 搜索候选关键词
  -> Vector Retriever: 补充语义证据
  -> Merge: 优先章节号更早且事件类型匹配的证据
  -> Evidence Guard
  -> LLM
```

排序规则：

```text
score = semantic_score * 0.35
      + keyword_score * 0.25
      + event_type_score * 0.25
      + early_chapter_score * 0.15
```

对于 `sequence_first`，如果候选中存在高置信时间线事件，应优先按 `chapter_no` 升序选择，而不是只按向量相似度。

### 7.3 时间线总结问题

```text
timeline_summary
  -> Timeline Retriever
  -> 按 chapter_no 升序
  -> 分段摘要
```

回答必须按章节顺序输出。

### 7.4 章节定位问题

```text
chapter_lookup
  -> Keyword Retriever
  -> Vector Retriever
  -> 按首次出现章节排序
```

如果用户问“首次出现在哪章”，本质上也要套用 `sequence_first` 约束。

## 8. Evidence Guard 设计

Evidence Guard 是 LLM 前的保护层，用于阻止明显错误的上下文进入最终回答。

### 8.1 顺序型保护规则

如果问题是 `sequence_first`：

1. 如果召回结果全是后期章节，但没有早期候选，回答前应提示证据不足。
2. 不允许仅根据一个后期“进入”章节断言它是第一个。
3. 必须在上下文中显式提供最早候选章节。
4. 如果多个候选都可能是第一次，回答应列出不确定点。

### 8.2 上下文标注

传给 LLM 的上下文要增加证据类型：

```text
【时间线候选 | world_entry | 第6章 这是，真实的世界 | confidence=0.72】
...

【向量召回 | 第3498章 进入 | score=0.81】
...
```

这样模型能区分“时间线证据”和“普通相似片段”。

## 9. 回答 Prompt 修改

v0.2 Prompt 新增：

```text
如果用户询问“第一个、第一次、首次、最早、最开始”等顺序问题，你必须优先依据章节号最早且事件类型匹配的证据回答。
如果提供的证据主要来自后期章节，不能断言它就是第一个。
如果没有足够证据确认顺序，回答“当前证据不足以确认第一个/首次”，并列出已找到的候选章节。
回答必须说明依据的章节号和证据类型。
```

## 11. 前端修改

Vue 页面新增：

1. 查询分析显示：
   - 问题类型
   - 识别出的实体
   - 检索路由

2. 时间线证据区：
   - 事件类型

   - 构建时间线索引

## 12. 数据质量风险

1. 规则抽取可能误判。
2. 某些世界名不会在进入章节明确出现。
3. 原文存在缺章、重复章、空章节。
4. 同一事件可能跨多个 chunk。

处理策略：

1. 保留置信度。
2. 保留证据片段和章节号。
3. 允许前端显示多个候选，不强行唯一化。
4. 后续引入 LLM 辅助抽取和人工校正文件。

## 13. v0.2 验收目标

用以下问题测试：

```text
苏晓进入的第一个世界是什么？
苏晓第一次回归乐园发生在哪些章节附近？
斩龙闪最早在哪章出现？
苏晓第一次获得青钢影能力是在什么时候？
按章节顺序整理苏晓早期进入过的世界。
```

预期：

1. 不应再把第3498章《进入》的 Fate/Zero 误判为第一个世界。
2. 如果证据不足，应明确说不足，而不是编造。
3. 顺序型问题必须展示时间线候选。
4. 回答必须包含章节引用。
