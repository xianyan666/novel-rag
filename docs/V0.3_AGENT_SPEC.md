# v0.3 Agent Spec：实体索引、实体时间线与澎湃风格前端

版本：v0.3  
日期：2026-07-04  
依赖文档：[V0.3_DESIGN.md](./V0.3_DESIGN.md)  
基线：v0.2 时间线 RAG

## 1. 实施目标

在 v0.2 基础上新增实体索引、实体提及、实体生命周期和实体关系能力，并升级 Vue 前端为澎湃 OS 风格启发的知识工作台。

核心问题：

```text
斩龙闪第一次出现在哪？
斩龙闪后续发生了哪些变化？
莫蕾第一次登场在哪？
莫蕾和苏晓有哪些交集？
```

v0.3 必须让这些问题走实体索引，而不是只走向量检索或事件时间线。

## 3. 实施顺序

### 阶段 1：实体种子配置

创建 `config/entities.seed.json`。

MVP 初始种子至少包含：

```json
[
  {
    "name": "苏晓",
    "type": "character",
    "aliases": ["白夜"]
  },
  {
    "name": "斩龙闪",
    "type": "item",
    "subtype": "weapon",
    "aliases": ["斩龙之刃"]
  },
  {
    "name": "莫蕾",
    "type": "character",
    "aliases": []
  },
  {
    "name": "青钢影",
    "type": "skill",
    "aliases": []
  }
]
```

要求：

1. 种子文件 UTF-8。
2. 不写死在代码中。
3. 支持后续新增实体。

### 阶段 2：实体构建脚本

创建 `scripts/build_entities.py`。

命令：

```powershell
python scripts/build_entities.py --project reincarnation_paradise
```

输入：

```text
config/entities.seed.json
data/{project_id}/chunks.jsonl
```

输出：

```text
entities.jsonl
entity_mentions.jsonl
entity_timeline.jsonl
entity_relations.jsonl
entity_index.json
```

实现要求：

1. 对每个种子实体及 aliases 扫描所有 chunks。
2. 每次命中生成一条 mention。
3. 每个实体按最早 mention 生成 `first_seen_chapter`。
4. 对命中 chunk 根据规则抽取 entity_timeline。
5. 在同一 chunk 内若出现两个以上实体，根据关系词抽取 relation。
6. 所有 evidence 最长 300 字。
7. 所有输出按章节号升序。

### 阶段 3：实体 ID 与归并

实体 ID 规则：

```text
{project_id}_{type}_{slug_or_hash}
```

中文实体名可用稳定 hash，避免路径和编码问题。

示例：

```text
reincarnation_paradise_item_a13f92c0
```

归并规则：

1. `name` 和 `aliases` 都指向同一 entity_id。
2. 如果别名命中多个实体，标记 alias conflict。
3. 同一 chunk 同一实体只生成一条 mention。

### 阶段 4：实体时间线规则

在实体命中 chunk 中匹配事件词。

物品：

```text
获得 -> item_obtained
强化/升级/品质提升 -> item_upgrade
修复/重铸 -> item_repair
吞噬/融合/进化 -> item_evolution
破损/损毁 -> status_changed
```

技能：

```text
获得/掌握 -> skill_obtained
提升/升级 -> skill_upgrade
觉醒/激活/突破 -> skill_awakened
```

人物：

```text
登场/出现/遇到 -> character_intro 或 character_interaction
合作/交易/交手/追杀/谈判 -> character_interaction
加入 -> faction_joined
背叛/离开 -> faction_left 或 relation_changed
```

每个实体必须至少生成一条 `first_seen` 时间线事件。

### 阶段 5：实体关系抽取

关系抽取输入：同一 chunk 中共同出现的实体。

关系词映射：

```text
持有/拿着/装备/佩戴 -> owns
使用/施展 -> uses
强化/升级/修复 -> upgrades
加入/成员 -> member_of
合作/盟友/队友 -> ally_of
敌人/追杀/交手 -> enemy_of
遇到/见到 -> meets
交易/谈判/委托 -> interacts_with
位于/来自 -> located_in
```

如果只共同出现但无明确关系词：

```text
relation_type = related_to
confidence <= 0.45
status = candidate
```

关系必须包含：

```text
source_entity_id
target_entity_id
relation_type
chapter_no
chunk_id
evidence
confidence
```

### 阶段 7：问题分类器升级

修改 `question_classifier.py`，新增类型：

```text
entity_first_seen
entity_timeline
entity_profile
entity_relation
entity_mentions
```

规则：

```text
第一次出现/首次出现/最早出现/首次登场 -> entity_first_seen
后续变化/发生了什么变化/成长/升级/强化/经历 -> entity_timeline
档案/介绍/总结/资料 -> entity_profile
关系/交集/互动/和谁有关 -> entity_relation
出现在哪些章节/相关章节 -> entity_mentions
```

注意：

1. 如果问题既包含“第一次”又包含实体名，优先 `entity_first_seen`。
2. 如果问题包含“进入的第一个世界”，仍走 v0.2 的 `sequence_first`，不要误判为实体。

### 阶段 8：查询服务升级

修改 `query_service.py` 或 `retrieval_router.py`：

1. 先执行问题分类。
2. 再执行实体检测。
3. 若为实体问题，优先调用 `entity_query_router`。
4. 普通问答继续使用 v0.2 路由。
5. LLM prompt 中加入实体证据块。

实体证据块格式：

```text
【实体提及 | 斩龙闪 | 第8章 斩龙之刃 | confidence=0.95】
...

【实体时间线 | item_upgrade | 第N章 标题 | confidence=0.82】
...

【实体关系 | 苏晓 owns 斩龙闪 | 第N章 标题 | confidence=0.85】
...
```

回答规则：

1. 首次出现问题必须以最早 mention 为依据。
2. 后续变化问题必须按章节升序。
3. 关系问题必须列出关系类型和证据章节。
4. 证据不足时必须明确说明。

## 5. 完成定义

v0.3 完成必须满足：

1. 实体索引文件全部生成。
2. 至少支持种子实体：苏晓、斩龙闪、莫蕾、青钢影。
3. `斩龙闪第一次出现在哪？` 不再只依赖向量检索。
4. `斩龙闪后续发生了哪些变化？` 能返回按章节排序的实体时间线候选。
5. `莫蕾和苏晓有哪些交集？` 能返回关系候选或明确证据不足。
6. 前端能展示实体库、实体详情、实体时间线和实体关系。
7. 前端整体改为澎湃 OS 风格启发的浅色通透工作台。
8. 原文文件未被修改。

## 6. 注意事项

1. 不要一次性尝试自动抽取所有实体，先用种子实体跑通链路。
2. 低置信实体和关系必须标为 candidate。
3. 不要使用小米商标、官方图标或官方素材。
4. Windows PowerShell 中文输出可能乱码，脚本提示尽量使用 ASCII，Python 文件保持 UTF-8。
5. 如果某实体名很短或歧义大，必须增加 aliases 或人工确认。
